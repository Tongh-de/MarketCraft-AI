# MarketCraft AI 产品需求文档（PRD）

> 文档版本：V1.0  
> 产品版本：MVP / v0.10.0 基线  
> 文档状态：待评审  
> 更新日期：2026-08-23  
> 产品定位：面向跨境电商团队的对话式 AI 创作与运营工作台

## 1. 文档目的

本文档定义 MarketCraft AI 从商品素材输入到内容生产、人工审核、多平台上架、经营数据回流和持续优化的完整产品链路，并明确统一产品入口、Skill 插件、外部服务接口、安全审批和分阶段交付标准。

本文档同时作为产品、设计、前端、后端、AI 应用、测试与后续外部系统联调的共同基线。未在当前版本真实联调的能力会明确标记为“规划中”或“Live 待联调”，不得将 Mock 演示描述为真实生产能力。

## 2. 产品概述

### 2.1 背景与问题

跨境电商团队在新品上线时，通常需要在图片处理、模特试穿、短视频、竞品分析、商品文案、海报设计、平台上架、库存校验和经营复盘之间频繁切换。现有工具往往是彼此割裂的：生成工具只负责素材，ERP 只负责库存，平台后台只负责上架，数据分析又在另一套系统中完成。

MarketCraft AI 希望把这些环节统一到一个对话式工作台中。用户只需上传商品图并描述目标，系统就能生成可解释的执行计划，按需调用 Skill 和外部服务，产出可编辑草稿，并在高风险写操作前暂停等待人工审核。

### 2.2 一句话定位

MarketCraft AI 是一个可对话、可扩展、可连接实时业务系统的 AI 电商工作台，帮助团队完成“商品图 → 多维素材 → 竞品洞察 → 文案/海报/视频 → 审核上架 → 数据回流 → 优化建议”的闭环。

### 2.3 产品目标

1. 用统一入口承载完整电商链路，降低多工具切换成本。
2. 让非技术用户通过自然语言发起任务，并能看懂系统将执行什么。
3. 通过 Skill 插件机制持续增加新场景，而不把业务流程写死在单一模型或供应商上。
4. 通过外部服务适配器连接 ComfyUI、即梦 AI、电商平台、ERP 和审批工具。
5. 在发布、库存、履约等写操作上保留明确的人机协同与审计边界。
6. 将曝光、点击、转化、广告、退货和库存数据回流到同一产品中，形成优化闭环。

### 2.4 非目标

当前阶段不建设完整自营电商商城前台，不替代 ERP/WMS/广告平台的全部功能，不承诺无人值守的全自动发布，也不将竞品素材直接复制为新作品。

## 3. 目标用户与角色

| 角色 | 核心任务 | 主要权限 |
| --- | --- | --- |
| 电商运营 | 发起商品创作、准备上架、查看经营建议 | 创建任务、编辑草稿、提交审核、读取数据 |
| 视觉/内容人员 | 调整图片、海报、视频和商品文案 | 编辑素材与版本、导出内容 |
| 审核人 | 检查品牌、平台规则、价格和库存 | 批准或驳回上架/业务写操作 |
| 管理员 | 配置 Skill、外部服务、权限和密钥引用 | 插件生命周期、连接器配置、审计查询 |
| 负责人 | 查看业务结果和执行风险 | 查看指标、报告、审批与异常 |

四眼审批要求：提交人与审核人必须为不同用户。系统需记录角色、动作、时间、版本、审批意见和外部执行结果。

## 4. 产品原则

1. **一个入口**：用户统一从 `/app` 进入产品，专业模块在同一外壳中切换。
2. **先计划、后执行**：对话输入先生成执行计划，用户可以查看和调整。
3. **草稿优先**：素材、文案、海报和上架内容默认生成草稿，不直接发布。
4. **能力可插拔**：业务 Skill 与模型/平台连接器分层，避免被单一供应商锁定。
5. **真实边界明确**：Mock、Live、Pending Configuration 状态必须清晰可见。
6. **高风险操作可控**：发布、改价、改库存、履约、广告调整需要显式确认或审批。
7. **全程可追踪**：每次任务保留输入、计划、工具调用、版本、审批和结果轨迹。

## 5. 产品信息架构

统一产品外壳包含以下一级模块：

1. AI 工作台：对话输入、文件上传、任务计划与跨模块进度。
2. 商品创作：商品理解、多角度图、模特试穿、视频和素材管理。
3. 竞品分析：竞品图片解析、差异化机会和原创创作 Brief。
4. 海报设计：模板/AI 海报、可编辑图层、版本和多尺寸导出。
5. 审核与上架：商品包、平台适配、人工审核、发布和结果回写。
6. 经营优化：指标回流、平台对比、问题诊断和实验建议。
7. 订单与库存：订单导入、库存校验、补货/履约决策和异常隔离。
8. Skill 插件：Skill 创建、编辑、自动修订、版本、启停和测试调用。
9. 外部服务：模型、平台、ERP、通知等连接器的统一配置与状态管理。

原 `/studio`、`/competitors`、`/poster-editor`、`/listing-workbench`、`/performance-insights` 和 `/dashboard` 页面作为内部模块及兼容地址保留，不再作为用户理解产品的独立入口。

## 6. 完整业务链路

### 6.1 主链路

1. 用户新建商品任务并上传一张或多张商品原图。
2. 系统识别商品类目、颜色、材质、版型、卖点和可能的平台需求。
3. 用户选择或通过对话指定输出：多角度图、场景图、模特试穿图、海报、短视频。
4. Agent 选择适用 Skill，再由 Skill 选择具备对应能力的外部服务连接器。
5. 系统生成素材草稿并保留原图关联、模型参数、Prompt 和版本信息。
6. 用户可上传竞品图，系统从构图、色彩、场景、卖点和品牌差异五个维度进行分析，输出原创创作建议。
7. 系统基于商品信息、品牌知识和平台规则生成标题、卖点、描述、标签和视频脚本。
8. 用户在海报编辑器中继续调整文字、颜色、位置、尺寸和图层。
9. 系统组装多平台上架包，并校验必填字段、图片规格、价格、库存和内容一致性。
10. 提交人与审核人完成四眼审批；驳回时返回具体原因并形成新版本。
11. 审核通过后，通过平台适配器执行发布；幂等键避免重复上架。
12. 系统读取订单、库存、曝光、点击、加购、成交、广告和退货数据。
13. 经营优化 Skill 基于数字证据生成只读建议和可验证实验。
14. 用户确认后进入下一轮创作、投放或运营调整。

### 6.2 对话输入如何变成执行

当用户输入“上传这件夹克，生成模特试穿图和 TikTok 海报，然后准备上架草稿”时，系统执行以下过程：

1. **理解目标**：识别商品、目标平台、期望产物和是否包含外部写操作。
2. **补齐信息**：缺少商品类目、尺码、品牌限制或目标市场时，仅询问必要问题。
3. **生成计划**：将任务拆为商品理解、试穿生成、海报生成、文案生成和上架包五个步骤。
4. **路由 Skill**：按触发词、能力标签、风险等级和当前状态选择已启用 Skill。
5. **选择服务**：从连接器中选择支持对应能力且状态可用的 ComfyUI、即梦 AI 或其他服务。
6. **执行低风险步骤**：读取数据、生成素材和创建草稿可以自动执行，并实时返回进度。
7. **暂停高风险步骤**：发布、改价、改库存、履约或广告调整进入待审核状态。
8. **结果回写**：保存产物、版本、调用状态、耗时、错误和业务对象关联。
9. **继续对话**：用户可以说“把背景改成海边”“换成 9:16”“只发 TikTok”，系统基于当前任务继续编辑。

## 8. Skill 插件体系

### 8.1 定位

Skill 是可复用的业务能力说明与执行策略，负责定义“什么时候触发、需要哪些输入、能做什么、允许调用哪些工具、风险等级是什么”。外部服务连接器负责“具体由哪个供应商或业务系统执行”。两者分离后，同一个商品素材 Skill 可以使用 ComfyUI、即梦 AI 或其他供应商，而不需要重写业务流程。

### 8.2 Skill Manifest

每个 Skill 至少包含：`plugin_id`、名称、描述、版本、状态、Instructions、触发词、能力标签、工具绑定、风险等级、是否内置、是否可编辑、变更历史、审计日志和更新时间。

### 8.3 生命周期

`Draft → Enabled → Disabled`。新建 Skill 默认为 Draft；手动编辑或 AI 自动修订后版本号递增并回到 Draft；只有管理员重新检查并启用后，路由器才能调用该版本。内置 Skill 默认启用且不可直接自动改写，如需定制应复制为自定义 Skill。

### 8.4 自动编辑

用户以自然语言提出修改要求，例如“增加低库存判断，并要求每条建议附带原始指标”。系统应生成差异说明，更新 Instructions/能力/工具绑定，增加补丁版本，记录修改人和变更原因，并将状态置为 Draft。自动编辑不能绕过权限、扩大到未授权工具或自动启用新版本。

### 8.5 插入与调用

1. 管理员创建或编辑 Skill。
2. 系统校验 Manifest、工具绑定和风险等级。
3. 管理员启用 Skill。
4. 对话路由器基于触发词、能力和上下文选择 Skill。
5. Skill 生成工具调用计划。
6. 只读或生成类工具可以执行；写操作进入审批。
7. 系统记录执行 ID、Skill 版本、命中触发词、工具列表和结果。

## 9. 外部服务接口模块

### 9.1 连接器类型

| 类型 | 内置示例 | 主要能力 |
| --- | --- | --- |
| 创作生成 | ComfyUI、即梦 AI | 多角度图、模特试穿、海报、视频 |
| 电商平台 | Amazon、TikTok Shop、Shopify | 商品发布、订单、经营数据读取 |
| 业务系统 | ERP | 商品、库存、订单和履约状态 |
| 通知审批 | 飞书 | 审批通知、结果回写 |
| 自定义服务 | 企业内部 API | 由管理员声明能力与鉴权方式 |

### 9.2 配置字段

连接器需要保存服务 ID、名称、类型、说明、Base URL、鉴权方式、密钥引用、能力列表、运行模式、连接状态、是否内置、审计日志和更新时间。平台只保存密钥引用，例如 `env:JIMENG_API_KEY`，不在业务数据中保存明文密钥。

### 9.3 状态与边界

- Mock：确定性演示，可验证业务流程，但未访问真实外部服务。
- Live / Pending Configuration：已保存真实服务配置边界，但尚未完成网络和凭证联调。
- Live / Connected：只有真实鉴权、健康检查和最小业务调用通过后才能显示。
- Disconnected：服务不可用或被管理员停用，路由器不得选择。

### 9.4 统一调用约定

所有连接器应接受统一上下文：`execution_id`、`tenant_id`、`actor`、`capability`、`payload`、`idempotency_key`、`timeout` 和 `trace_id`。返回结果至少包含状态、外部任务 ID、产物或数据、错误分类、是否可重试、供应商原始状态摘要和审计时间。

外部调用应具备超时、有限重试、指数退避、熔断、限流、幂等、失败隔离和可观测性。供应商返回未知状态时不得假设成功。

## 10. 状态机与异常处理

### 10.1 通用任务状态

`Draft → Planned → Running → Waiting for Review → Approved → Executing → Completed`，异常分支为 `Failed / Partially Completed / Cancelled`。

### 10.2 上架包状态

`Draft → Pending Review → Approved / Rejected → Published / Publish Failed`。驳回后需基于原版本创建新版本，保留旧版本审计记录。

### 10.3 异常原则

1. 单个素材生成失败不删除已经成功的产物。
2. 可重试错误与不可重试错误必须区分。
3. 外部平台超时后先查询幂等结果，再决定是否重试。
4. 数据不完整时返回质量提示，不编造缺失指标。
5. 高风险步骤失败后不得自动降级为绕过审批的替代路径。

## 11. 数据与核心对象

核心对象包括：用户与角色、商品、原始素材、创作任务、创作产物、竞品分析、海报项目及版本、商品上架包、审批记录、平台发布记录、订单、库存快照、经营指标快照、优化报告、Skill Manifest、外部服务连接器和审计事件。

所有生成产物需关联商品 ID、任务 ID、来源素材、生成参数、服务 ID、Skill 版本、创建人和创建时间。所有外部写操作需关联审批记录和幂等键。

## 12. 权限、安全与合规

1. 登录与租户隔离：用户只能访问所属组织和被授权业务对象。
2. 最小权限：Skill 只能调用 Manifest 中明确绑定的工具。
3. 密钥安全：仅保存 Secret Reference，真实密钥由环境变量或密钥管理服务提供。
4. 图片安全：上传文件进行类型、大小和恶意内容校验；原始素材与生成素材分开存储。
5. 内容合规：生成内容标记 AI 来源，支持品牌词、禁用词和平台规则检查。
6. 人工审批：发布、改价、改库存、履约和广告变更默认属于高风险操作。
7. 审计：记录输入、输出摘要、模型/服务、版本、审批、执行结果和异常。
8. 竞品边界：竞品分析用于提取模式和机会，不应直接复刻受保护的视觉资产或文案。

## 13. 非功能需求

### 13.1 性能

- 普通页面和查询接口的目标响应时间由真实部署环境压测后确定。
- 长耗时生成任务必须异步执行，前端通过轮询或事件流查看进度。
- 图片和视频使用对象存储及 CDN，API 不长期承载大文件 Base64。

### 13.2 可靠性

- 外部调用具备超时、重试、熔断和幂等保护。
- 长任务支持断点状态与失败重跑。
- 关键写操作不可因页面刷新而重复执行。

### 13.3 可观测性

- 每次任务有唯一 Trace ID 和 Execution ID。
- 记录各步骤耗时、成功率、错误分类、供应商状态和人工等待时长。
- 支持按商品、任务、Skill、服务和平台查询执行轨迹。

### 13.4 可扩展性

- 新增 Skill 不要求修改核心路由器代码。
- 新增服务只需实现统一连接器协议并声明能力。
- 平台字段映射、品牌规则和审批策略应配置化。

## 14. 指标体系

### 14.1 产品指标

- 首次有效产物完成率。
- 从上传商品图到上架草稿的中位耗时。
- 单商品跨工具切换次数。
- 草稿一次审核通过率。
- 用户对 AI 产物的采纳率和人工修改率。

### 14.2 AI 质量指标

- 商品关键属性识别准确率。
- 商品一致性人工评分。
- 生成图片可用率。
- 文案事实错误率与平台规则通过率。
- 竞品建议的差异化和可执行性评分。

### 14.3 系统指标

- 任务成功率、部分成功率和失败率。
- 外部连接器可用率、超时率和重试率。
- Skill 路由命中率与人工改路由比例。
- 重复发布拦截次数。
- 高风险操作审批覆盖率。

指标目标值需在真实用户试运行和基线采集后确定；当前 Mock 演示数据不作为生产 KPI 结果。

## 15. 分阶段交付计划

### Phase 0：可演示产品基线（已完成）

- 统一 `/app` 产品外壳。
- 商品创作、竞品分析、海报、上架、经营分析、订单库存模块。
- Skill/Plugin 注册体系和可编辑 Skill 生命周期。
- ComfyUI、即梦 AI、Amazon、TikTok Shop、Shopify、ERP、飞书 Mock 连接器。
- 四眼审批、幂等发布、审计轨迹、Mock/Live 边界。
- 48 项自动化测试及基础代码质量检查。

### Phase 1：真实创作服务联调

- 接入 ComfyUI 工作流 API，完成图片任务提交、状态查询和结果回收。
- 接入即梦 AI 图片/视频能力，完成鉴权、参数映射和失败处理。
- 建立对象存储、素材版本和生成成本记录。
- 用真实商品样例建立图片一致性与可用率评测集。

### Phase 2：真实平台上架

- 优先选择一个目标平台完成沙箱或测试店铺联调。
- 完成类目、属性、图片、价格、库存字段映射。
- 完成审核、幂等、回查、失败重试和审计闭环。

### Phase 3：业务数据回流

- 接入 ERP 与平台订单、库存、经营数据读取接口。
- 建立增量同步、对账、数据延迟和质量告警。
- 将优化建议转换为可审批的实验任务。

### Phase 4：可运营的 Agent 平台

- 提供 Skill 测试、灰度、回滚、效果评测和版本对比。
- 提供连接器监控、配额、成本和供应商路由策略。
- 支持更多业务团队、品牌和租户级配置。

## 16. MVP 验收标准

1. 用户只通过 `/app` 即可访问全部核心模块。
2. 用户输入自然语言后能看到结构化执行计划，而不是只得到一段回复。
3. 上传商品图后可以产生多维素材、模特试穿、海报或视频任务中的至少一种可验证结果。
4. 用户可以上传竞品图并获得五维分析和差异化 Brief。
5. 海报文字、颜色、位置和尺寸可编辑并保留版本。
6. 商品上架包必须经过不同用户审批后才能执行发布。
7. 相同幂等键不会触发重复发布。
8. Skill 可创建、编辑、自动修订、启停和生成调用计划；修订后自动回到 Draft。
9. 外部服务可以配置能力、模式、鉴权和密钥引用，Mock 与 Live 状态清晰。
10. 经营报告包含数据来源、时间范围、数字证据和数据质量提示。
11. 每个任务能够查看输入、Skill 版本、服务、审批和结果轨迹。
12. 未真实联调的服务不得显示为 Live Connected。

## 17. 风险与待决策事项

| 风险/决策 | 影响 | 建议 |
| --- | --- | --- |
| 商品外观在 AI 生成中发生变化 | 影响上架真实性与退货 | 建立商品一致性评测和人工抽检门槛 |
| 不同平台字段和规则差异大 | 增加适配成本 | MVP 先选一个平台真实打通，再扩展 |
| 即梦 AI/ComfyUI 能力和计费差异 | 影响路由与成本 | 统一能力协议，保存供应商成本和质量数据 |
| 实时数据口径不一致 | 可能产生错误建议 | 显示来源、时间和数据质量，不确定时降级 |
| Skill 自动编辑扩大权限 | 产生安全风险 | 自动修订后回 Draft，启用前做工具与权限检查 |
| 视频生成耗时和失败率较高 | 影响用户等待体验 | 异步任务、进度反馈、局部重试和供应商切换 |

待决策事项：首个真实上架平台、首个重点商品类目、ComfyUI 部署方式、即梦 AI 可用接口范围、对象存储方案、真实 ERP 类型、试点团队规模和首批 KPI 基线。

## 18. 当前 API 基线

- `/api/v1/creation/*`：商品创作、Skill 和创作插件。
- `/api/v1/poster-projects/*`：可编辑海报项目与版本。
- `/api/v1/listing-packages/*`：上架包、审核和发布。
- `/api/v1/performance/*`：经营指标快照与优化报告。
- `/api/v1/operations/*`：订单、库存、补货和履约。
- `/api/v1/platform/skill-plugins/*`：自定义 Skill 创建、编辑、自动修订、启停和调用计划。
- `/api/v1/platform/external-services/*`：外部连接器配置和健康状态。

接口详细字段以 `/docs` 中的 OpenAPI 定义为准。真实服务接入后仍需补充回调、异步任务、配额、成本和供应商错误码映射。
